# Actividad: Diseño de Propuesta de Práctica Temática (Proyecto Pequeño)

## Descripción general
En esta actividad vas a diseñar una propuesta de práctica temática para un proyecto pequeño enfocado en programación de sistemas y uso de terminal. La prioridad es **documentar, justificar y planear** la idea antes de programar.

Esta plantilla está pensada para GitHub Classroom y para estudiantes que trabajarán con recursos limitados (por ejemplo, uso gratuito de Codex u otra IA con límite de consultas).

## Objetivo de aprendizaje
Al finalizar la actividad, el estudiante será capaz de:

- Definir un problema técnico pequeño y viable.
- Justificar la selección de lenguaje para resolverlo.
- Diseñar una estructura de repositorio clara y mantenible.
- Documentar caso de uso, alcance y plan de pruebas.
- Implementar (opcionalmente) un prototipo mínimo alineado a la propuesta.

## Lenguajes permitidos
- ARM64 Assembly
- C
- Python
- Bash

## Reglas para mantener el proyecto pequeño
- Enfócate en **una sola función principal** del sistema.
- Limita la implementación a una versión mínima funcional.
- Evita características avanzadas no esenciales.
- Usa pocos archivos y funciones cortas.
- No utilices frameworks, bases de datos, Docker, nube ni APIs externas.
- Si eliges ARM64 Assembly, el programa debe ser muy pequeño y de consola.

## Entregables esperados
1. `docs/propuesta.md` completo.
2. `docs/caso_de_uso.md` completo.
3. `docs/estructura_repositorio.md` revisado y adaptado al tema.
4. `docs/plan_de_pruebas.md` con casos definidos.
5. `tests/test_plan.md` con checklist final.
6. Prototipo mínimo en `src/main.<ext>` (opcional pero recomendado).
7. Script `scripts/run.sh` ajustado al lenguaje elegido.

## Instrucciones para el estudiante
1. Elige un tema pequeño y realista.
2. Completa primero la documentación en `docs/`.
3. Revisa alcance y limita el proyecto a algo viable en poco tiempo.
4. Define pruebas manuales simples.
5. Si el tiempo alcanza, implementa un prototipo mínimo.
6. Verifica que el repositorio esté ordenado y entendible.

## Ejemplos de posibles temas
- Mini Toolkit en ARM64
- Asistente de Estudio en Terminal
- Reporteador de Información del Sistema
- Organizador de Archivos
- Juego de Aprendizaje en Línea de Comandos

## Criterios generales de evaluación
- Claridad del problema y justificación.
- Viabilidad técnica del alcance.
- Coherencia entre caso de uso, estructura y pruebas.
- Orden y calidad de la documentación.
- (Opcional) Funcionamiento básico del prototipo.

## Nota importante
En esta actividad **primero se documenta** (propuesta, caso de uso, estructura y pruebas) y **después, de forma opcional**, se implementa un prototipo pequeño.
